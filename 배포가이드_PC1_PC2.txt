 2. PC1 (DB 서버, 10.178.187.65) — 한 번만 하는 설정
================================================================

(1) PostgreSQL 설치, 서비스 자동 시작 권장
    # 관리자 PowerShell
    Get-Service *postgres*                          # 서비스명 확인 (예: postgresql-x64-17)
    Set-Service -Name postgresql-x64-17 -StartupType Automatic

(2) postgresql.conf
    listen_addresses = '*'

(3) pg_hba.conf  맨 아래 추가 (PC2 허용)
    host  all  all  10.178.187.220/32  scram-sha-256
    # 테스트용 전체 허용:  host  all  all  0.0.0.0/0  scram-sha-256

(4) PostgreSQL 재시작 + Windows 방화벽 5432(TCP) 인바운드 허용

(5) cache/queue/c cable DB 생성 (1회)
    psql -U postgres -f db/setup_production_databases.sql

[PC1 재기동 후]
    net start postgresql-x64-17        # (자동시작이면 불필요)
    # 다른 PC(PC2)에서 확인:  Test-NetConnection 10.178.187.65 -Port 5432

 7. 문제 해결
================================================================

[secret_key_base 에러 / 컨테이너 재시작 루프]
  -> PC2 .env 에 RAILS_MASTER_KEY 누락. config/master.key 내용을 그대로 복사.

[DB 연결 실패]
  -> PC1 방화벽 5432, pg_hba.conf(PC2 IP 허용), .env 의 DB_HOST(10.178.187.65)/DB_PASSWORD 확인.
  -> cache/queue/cable DB 가 생성됐는지 확인 (PC1 에서 setup_production_databases.sql).

[Blocked host]
  -> APP_HOST 에 실제 접속 주소(IP:포트)가 포함돼야 함.

[실시간 채팅 안 됨]
  -> ALLOWED_ORIGINS 에 브라우저 URL(http://IP:3001)이 포함돼야 함.

[DB 서버(PC1) 재기동 후]
  -> PC1 에서 PostgreSQL 서비스만 시작하면 됨 (설정/방화벽은 영구 적용).
     net start postgresql-x64-17   (자동시작 권장)
  -> PC2 앱은 다음 요청에 자동 재연결 — PC2 에서 할 일 없음.
